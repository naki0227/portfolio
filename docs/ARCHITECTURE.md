# Portfolio architecture

## 目的

人物像・制作物・設計経験を閲覧できる公開向けポートフォリオ。主な6作品から、公開リポジトリ全体、インターン・技術・学歴・活動へ読み進められる構成。コピーは抽象的な宣言より具体的な経験を優先する。

## 責務と依存

| レイヤー           | ファイル                                                           | 責務                                                 |
| ------------------ | ------------------------------------------------------------------ | ---------------------------------------------------- |
| 公開データ         | content/portfolio.ts, experience.ts, archive.ts, repositories.json | 型・表示用の公開情報・確認日時                       |
| ページ             | app/page.tsx                                                       | セクションを組み立てる                               |
| セクション         | Hero, Project, EngineeringNotes, Experience, About                 | 意味的なHTMLを返すサーバー側コンポーネント           |
| 一覧UI             | RepositoryArchive                                                  | 入力・カテゴリ・展開状態を保持                       |
| 検索               | lib/portfolio-filter.ts                                            | 入力とカテゴリから結果を求める純粋関数               |
| 描画ライフサイクル | FlowBackground                                                     | 遅延読み込み、停止、可視状態、リサイズ、アンマウント |
| GPU境界            | lib/scene/create-flow-scene.ts                                     | カメラ、線、点、描画、GPUリソース解放                |
| 純粋な幾何         | lib/scene/surface.ts                                               | 時刻とパラメータから座標を求める                     |
| 静的背景           | FlowFallback                                                       | 同じ座標関数から初期HTMLのSVGを生成                  |
| スタイル           | app/styles/base.css, portfolio.css                                 | 基礎表示とページ固有のレスポンシブ構成               |

データ・幾何・検索処理はReactに依存しない。GPU境界はページ内容や検索を知らない。クライアント境界は背景と一覧UIに限定。API・DB・認証が不要なため、形だけのRepository/UseCase層は設けない。

## ADR-001: React + TypeScript

主要な作品、リポジトリ一覧、経歴を型で管理する。共通表示はコンポーネントにまとめ、内容の更新とUI変更を分ける。本人が使用経験のあるReactを利用し、継続して編集しやすくする。

## ADR-002: Vinext + Vite + Workers

既存の配信環境と互換性のあるスターターを継続利用。HTMLをサーバーから返すことで、初期の文章をクライアント描画に依存させない。

VinextはNext.js App Router互換のベータ実装であり、Next.js本体と同じ安定性を保証しない。本環境への配信互換性が採用理由で、静的ポートフォリオ一般の最小構成ではない。将来はAstroやNext.jsの静的生成も候補。アプリ固有コードにはCloudflare APIを持ち込まない。

## ADR-003: Three.jsへの変更

初版はCanvas 2Dの小さな格子だった。背景をよりリッチにする追加要望を受け、透視投影とポインターに応じた視点変化を持つ、画面全体の曲面へ変更した。

Three.jsを採用する理由は、カメラ・ジオメトリ・GPUリソースの扱いを既存ライブラリに任せ、独自のWebGL基盤を増やさないため。React Three Fiberは単一シーンには追加の抽象化が不要なため採用しない。

- Three.jsは動的importし、初期のコンテンツ経路から切り離す。
- 同じ純粋な表面関数を使ったSVGをHTMLとして返す。JavaScriptやWebGLが利用できなくても背景が成立する。
- 描画は約25fpsを上限とし、DPRを1.6に制限。
- 画面外、非表示タブ、停止操作、`prefers-reduced-motion`ではRAFを停止。
- WebGLコンテキスト喪失では継続描画を止め、静的背景を維持。
- Geometry・Material・Renderer、監視・イベント・RAFは破棄する。

代償はライブラリ転送量とGPU利用。描画は装飾に限定し、本文やナビゲーションは依存しない。WebGLの視覚確認は本実行環境では無効化されているため未実施。フォールバックの見た目・検索UI・静的内容はブラウザで確認する。

参考: https://threejs.org/docs/

## ADR-004: 公開一覧をスナップショット化

2026-09-17にGitHubで確認した42件の公開リポジトリを、ページ内で閲覧できるようにする。privateリポジトリは含めない。

実行時のAPI呼び出しを行わず、認証・レート制限・GitHub障害への依存を避ける。新規リポジトリはデータ更新が必要というトレードオフがある。ページに確認日を明示する。説明は公開READMEと本人の説明を短く要約し、未実装の機能・測定していない性能・共同制作の全実装を本人の成果として断定しない。

初期表示は12件、展開すると対象のすべてを表示。名前・技術・説明の複数語AND検索と分野フィルターを組み合わせる。該当なし状態とクリア操作を設ける。

## ADR-005: 標準HTMLと既存プリミティブ

作品詳細はdetails/summary。検索はInput、カテゴリはTabs、操作はButtonの既存プリミティブを利用。デザインは独自CSSで統一。スマートフォンでは縦に並べ、情報を削除しない。

## 情報の公開境界

掲載対象は本人の職業的プロフィール、公開作品、学歴、資格、活動・趣味。インターンの企業名と経験は掲載するが、内部資料・内部評価・選考情報・顧客情報は掲載しない。私生活や個人の連絡先は含めない。公開ソースとコメントにも同じ方針を適用する。

主な根拠は本人が共有した経験と各GitHub README。GitHubへのリンクを全件に付ける。StudyReelはApp Storeの開発者・掲載情報を確認。リポジトリ一覧に含まれる研究・企画・学習コードは、公開アプリ数と混同しない。

## 更新フロー

公開情報を確認 → contentを更新 → 型検査・ビルド → 検索・詳細・レスポンシブ確認 → GitHubと配信先へ反映。
